# План роботи до реалізації

| Поле | Рішення |
| --- | --- |
| Проблема | Для кількох страв потрібно вручну виписувати інгредієнти, об’єднувати повтори та шукати ціни у двох магазинах. Повторюється під час планування покупок. Фактичну частоту користувач підтверджує після пробного використання. |
| Поточний процес | Прочитати рецепти → виписати продукти → звести одиниці → відняти наявне → знайти товари АТБ/Сільпо → порахувати упаковки. Час до AI потрібно виміряти, а не оцінювати заднім числом. |
| Дані | Скопійовані довільним текстом рецепти; відкриті каталоги товарів АТБ і «Сільпо»; уточнення користувача. |
| Рівень | 2 — LLM + інструменти. Модель структурує текст і відповідає в чаті, окремі інструменти отримують актуальні ціни та детерміновано рахують упаковки. Донавчання не потрібне; послідовність інструментів задана програмою. |
| Ціль | Не менше 95% явно зазначених інгредієнтів виділено правильно; не вигадувати кількості; скоротити виміряний час підготовки й перевірки списку щонайменше удвічі на реальних випадках. Для цін показувати покриття, джерело, час і неповний підсумок при пропусках. |
| Ризики / fallback | Помилкова інтерпретація → цитати та редагування; різні одиниці → не зводити без правила; антибот/відсутній товар → явна помилка, позначений кеш або ручне додавання; різні регіони й фасування → показати контекст та вибраний товар. |

Цілі зафіксовано до тестування. Автоматичні перевірки не видаються за реальні покупки або користування протягом кількох днів.
