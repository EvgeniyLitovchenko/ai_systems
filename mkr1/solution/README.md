# Смак & Кошик

Локальний помічник для довільно скопійованих рецептів, списку покупок і порівняння товарів у Житомирі.

## Швидкий запуск

Потрібні Python 3.11 або новіший та встановлений Ollama.

```powershell
ollama pull qwen3.5:4b
ollama pull qwen3.5:9b
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python app.py
```

Відкрити **http://127.0.0.1:8765/**. Команди виконуються з папки `solution/`. Модель працює локально; інтернет потрібен лише для першого завантаження моделі та актуальних каталогів магазинів.

Якщо середовище вже створено в `mkr1/.venv`:

```powershell
..\.venv\Scripts\python app.py
```

Без GPU модель теж може працювати, але повільніше. Перевірений запуск: Windows, RTX 5070, Ollama, Qwen3.5 4B для розбору/чатів та Qwen3.5 9B для складніших оцінок ваги. Після відкриття внизу ліворуч має з’явитися «Модель готова». За потреби модель можна змінити змінною `RECIPE_MODEL`, модель оцінок — `ESTIMATE_MODEL`, адресу Ollama — `OLLAMA_URL`, порт застосунку — `PORT`. За замовчуванням доступ тільки з цього комп’ютера.

## Як користуватися

1. Вставити один або кілька рецептів без спеціального форматування. Кнопка «Додати .txt» також читає звичайний текстовий файл. Не потрібно вручну прибирати емодзі, кроки чи підписи фото.
2. Натиснути «Скласти список покупок». Кожен продукт має джерельну цитату; діапазони, невідомі кількості й точні повтори позначаються для перевірки.
3. Список згруповано за відділами магазину. Є фільтр категорій, множник порцій, ручне редагування та позначка «Є вдома». Продукти лише для подачі спочатку виключені, їх можна ввімкнути.
4. Під час пошуку цін модель автоматично оцінює вагу продуктів у штуках і невідомі частини кількостей **лише для попереднього кошика**. Оригінальна кількість не змінюється; під нею видно орієнтир для кошторису. Для спецій, соусів, цукру й олії без сумісної міри попередньо закладено одну упаковку. Кнопка «Запропонувати кількості» дозволяє окремо переглянути, відредагувати й явно застосувати оцінки до робочого списку. Ручні сумарні уточнення після зміни порцій треба переглянути.
5. Натиснути «Знайти ціни в магазинах». Звірити запропоновані товари; через «Змінити товар» можна обрати інший варіант або вручну внести підтверджені дані з каталогу. Посилання веде на товар. Програма не додає покупки до кошиків і не оформлює замовлень.
6. У картці «Запитайте про рецепт» доступний чат із поточними рецептами й обраними цінами. Вкладка «Просто чат» працює без передачі рецептів. Відповіді чату не змінюють список автоматично.
7. Зберегти список, скопіювати або завантажити його як текст. Збережені списки залишаються в локальній SQLite-базі; їх можна відкрити після перезапуску.

## Що означають ціни

- АТБ: Житомир, вул. Велика Бердичівська, 70б. Звичайна ціна, без умовної знижки за карткою АТБ.
- «Сільпо»: Житомир, вул. Грушевського Михайла, 5. Ціна й залишок саме цього каталогу відділення.
- Для фасованого товару ціна показана за упаковку; потрібна ціла кількість упаковок округлюється вгору.
- Для вагового товару використовується базова ціна за кг, а не відображення за 100 г. Кількість округлюється за кроком каталогу; фактична вага цілого овоча може відрізнятися.
- Штуки, ложки й невідомі кількості **не змінюються в оригінальному списку**. Для попереднього кошторису окремо використовується позначена оцінка ваги або припущення про одну упаковку продукту для комори. Це не точна маса реальних продуктів і не кількість, нібито взята з рецепта.
- Якщо не все пораховано, показується **«Не всі товари пораховані»** із покриттям. Він не визначає, який магазин дешевший.
- Кеш актуальний 30 хвилин. «Оновити» запитує каталог повторно. Старий кеш при збої помітно позначений, дата й час не оновлюються штучно.
- Суми орієнтовні, без доставки. Товарів і цін модель не вигадує: їх отримують окремі HTTP-адаптери. Відповідність інгредієнту все одно потрібно перевіряти.

## Перевірки

```powershell
python test_core.py
python evaluate.py
```

`test_core.py` перевіряє об’єднання, діапазони, одиниці, фасування, ціни й захист від нерелевантних товарів без мережі та LLM.
`evaluate.py` потребує запущеного `app.py`, Ollama та інтернету; повторює технічні запуски на трьох наданих рецептах із `../evidence/usage/`. Зберігає фактичні JSON-відповіді та метрики в `../evidence/technical/`. Це не вимірювання часу ручної роботи.

## Вимірювання для МКР

Кнопка «Вимірювання для МКР» зберігає фактично виміряний час до/після. Обидва значення мають стосуватися одного набору рецептів і однакового завдання. Час після включає читання результату, перевірку й виправлення, а не тільки генерацію моделі. Записи потрапляють у `../evidence/usage/measurements.jsonl`.

Задокументований ручний час користувача — **172 секунди для борщу й тушкованої капусти, без піци й без цін**. Порівнювати його з повною покупкою для трьох рецептів некоректно.

## Файли

- `app.py` — локальний сервер, історія, API та журнали;
- `core.py` — модель, цитати, агрегація, категорії й приблизні пропозиції;
- `stores.py` — адаптери двох обраних магазинів, кеш та арифметика упаковок;
- `web/` — інтерфейс;
- `test_core.py`, `evaluate.py` — перевірки.

Робоча база й кеш зберігаються в `mkr1/.runtime/` та не потрапляють у Git. Модель зберігає Ollama поза репозиторієм. Журнали в `evidence/` містять введені рецепти та відповіді; перед публікацією власних конфіденційних нотаток їх слід переглянути. Наявні приклади — рецепти, надані користувачем для цієї роботи.

Для перегенерації звіту після введення вимірювань: `python refresh_report.py`. Відео `../demo.mp4` — 80-секундний покроковий огляд із реальних збережених кадрів і українськими субтитрами, без озвучення. Для повторного збирання: встановити `requirements-dev.txt` та запустити `python build_demo.py`. Зручний запуск на вже налаштованому Windows-комп’ютері: подвійний клік `start.cmd`.
