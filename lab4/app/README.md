# Картки з конспекту

Простий локальний вебзастосунок: текст лекції → українські запитання, відповіді та дослівні цитати. Окрема сторінка bench взята з методичних матеріалів. Публікація не потрібна.

## Запуск

Потрібні Python 3.10+ і [Ollama](https://ollama.com/download). Python-залежностей для самого вебзастосунку немає. У Windows можна використовувати встановлений Python 3.13: `D:\Tools\Python\python.exe`.

З теки `lab4/app`:

```powershell
ollama pull qwen3:4b-instruct-2507-q8_0
ollama pull qwen3:4b-instruct-2507-q4_K_M
ollama create lab4-qa-q8 -f Modelfile.q8
ollama create lab4-qa-q4 -f Modelfile.q4
python app.py
```

Ollama має бути запущена окремо (застосунок Ollama або `ollama serve`). Якщо обидва теги вже встановлено, повторно завантажувати їх не потрібно.

- Картки: [http://localhost:8000](http://localhost:8000).
- Bench: [http://localhost:8000/bench.html](http://localhost:8000/bench.html).

Відкривайте сторінки через сервер, не подвійним кліком HTML. Сервер слухає лише `127.0.0.1`, передає запити в Ollama на `127.0.0.1:11434` та дозволяє bench працювати без зміни CORS-налаштувань. Сторінка карток звертається до `/generate`, а сервер використовує OpenAI-сумісний `/v1/chat/completions`. Bench використовує той самий API через локальний проксі.

## Використання

1. Вставте текст або відкрийте UTF-8 файл TXT/MD. Максимум — 3000 символів; довгу лекцію поділіть на фрагменти.
2. Оберіть 2–8 карток та модель. Q8 є основною за результатами перевірки якості; Q4 доступна для порівняння швидкості.
3. Натисніть «Створити картки». Під час запиту видно індикатор очікування.
4. Перевірте зміст і збережіть результат у JSON або CSV. CSV має UTF-8 BOM для відкриття в Excel.

JSON із вигаданою цитатою, повторними запитаннями чи незаповненими полями відхиляється. Дослівна цитата не гарантує правильного формулювання запитання — зміст потрібно переглядати. Мало фактів → менше карток; відсутність фактів → порожній список. Документи не зберігаються сервером.

## Параметри

`temperature=0`, `seed=1` зменшують випадковість. `reasoning_effort=none`: задача полягає у виділенні фактів; приховані міркування збільшують затримку. `max_tokens=1600` обмежує генерацію для 8 коротких карток. Контекст 8192 токени заданий у Modelfile: близько 3000 вхідних символів + системний промпт + до 1600 токенів відповіді, із запасом для української токенізації. Таймаут моделі — 180 с. При досягненні ліміту токенів незавершений результат не показується як успішний.

## Bench із методичних

`bench.py` є **дослівною копією** наданого скрипта; SHA-256: `d7b351d9ea99b53eccffe7629fccfd992c202085b3fc28939d73b4b0486cc18e`.
`web/client.js` і `web/style.css` скопійовані без змін. У `web/bench.html` змінено тільки посилання на картки, початкові адресу API й назву моделі; алгоритм вимірювань збережено.

Для вимірювань у терміналі встановіть залежність:

```powershell
python -m pip install -r requirements.txt
python bench.py --base-url http://localhost:11434/v1 --model lab4-qa-q8 --label before --reasoning-effort none --concurrency 1 2 4 --requests 16 --max-tokens 200 --output ../bench_results.csv
python bench.py --base-url http://localhost:11434/v1 --model lab4-qa-q4 --label after --reasoning-effort none --concurrency 1 2 4 --requests 16 --max-tokens 200 --output ../bench_results.csv
```

На вебсторінці задайте ті самі параметри: протокол OpenAI, модель Q8/мітка `before`, потім Q4/`after`; клієнтів `1,2,4`, запитів 16, токенів 200, temperature 0, без міркування. Натисніть «Завантажити CSV». Для понад 6 клієнтів використовуйте Python-скрипт. Основний CSV лабораторної створено оригінальним Python bench; додатковий `results/web_bench_check.csv` підтверджує перевірку вебсторінки з коротким навантаженням, це окремий запуск.

TTFT включає чергу, мережу й клієнтську обробку; tokens/s вимірюється після першого видимого токена. Throughput стосується всього рівня навантаження. Прогрів не входить у результати. Не запускайте інші GPU-задачі під час повторних вимірювань.

## Відтворення перевірки якості

```powershell
python quality.py --model lab4-qa-q8 --label before
python quality.py --model lab4-qa-q4 --label after
python test_app.py
```

`quality.py` містить 10 фіксованих тематичних текстів, використовує той самий `qa_core.py`, що й вебзастосунок, та зберігає повні запити/відповіді в `../results/`. Повторний запуск перезапише відповідний JSON. 12 контрактних тестів перевіряють валідацію, експорт та обробку помилок; вони не вимірюють семантичну якість моделі.

Додаткові експерименти до теорії: `extra_experiments.py` (Ollama), `small_model_experiment.py` (CUDA/PyTorch/Quanto; залежності в `experiment_requirements.txt`). Для меншої моделі потрібні завантажені ваги `Qwen/Qwen3-1.7B` в Hugging Face cache. Код ноутбука показує результати та пояснення. Великих ваг і середовищ Python у цій теці немає.
